---
title: Introduction
---

Thanks to Code Atlas's support for MDX, you can create your own custom components and use them directly within your MDX files. Code Atlas imposes very few restrictions on this.

In addition, we provide a wide range of built-in components for you to use:

<Cards cols="2">
  <Card title="Cards / Card">

    Arrange related content in a responsive card grid, with titles, optional icons, and rich content.

    [View documentation](/docs/components/cards)

  </Card>
  <Card title="Changelogs / Changelog">

    Present release notes with dates, titles, tags, and Markdown content. Sort entries by date or preserve their authored order.

  </Card>
  <Card title="CodeBlock">

    Turn code fences into highlighted examples with filenames, line numbers, highlighted lines, and a copy button.

    [View documentation](/docs/writting/code-blocks)

  </Card>
  <Card title="CodeDiff">

    Compare code before and after a change, with added and removed lines and their original line numbers.

    [View documentation](/docs/components/code-diff)

  </Card>
  <Card title="CodeGroup">

    Group related code examples into tabs so readers can switch between languages, files, or implementations.

    [View documentation](/docs/components/code-groups)

  </Card>
  <Card title="FAQ / Question">

    Organize common questions into expandable answers, with an optional question open by default.

    [View documentation](/docs/components/faq)

  </Card>
  <Card title="FileTree">

    Explain a project's directory structure with expandable folders, file icons, and nested paths.

    [View documentation](/docs/components/file-tree)

  </Card>
  <Card title="Hint / HintTitle / HintContent">

    Highlight notes, tips, and warnings. Compose a title and rich content, with optional collapsing.

    [View documentation](/docs/components/hint)

  </Card>
  <Card title="Image">

    Display captioned images with click-to-expand previews, Ctrl + scroll zoom, and dragging to inspect details. Markdown images receive the same preview automatically.

    [View documentation](/docs/components/image)

  </Card>
  <Card title="MermaidView">

    Render diagrams from Mermaid source, including flowcharts and sequence diagrams. Mermaid code fences also use this renderer.

    [View documentation](/docs/writting/mermaid)

  </Card>
  <Card title="PackageInstall">

    Show installation commands for npm, pnpm, Yarn, and Bun, with package-manager switching and command copying.

    [View documentation](/docs/components/package-install)

  </Card>
  <Card title="Preview">

    Display a live component example alongside its authored MDX source. Requires the experimental components-in-MDX option.

    [View documentation](/docs/components/preview)

  </Card>
  <Card title="Props / Prop">

    Document component APIs in a table of property names, types, default values, and descriptions. Each `Prop` defines one row inside `Props`.

  </Card>
  <Card title="Status">

    Mark a component's maturity and version milestones, including when it was introduced, deprecated, or stopped being supported.

    [View documentation](/docs/components/status)

  </Card>
  <Card title="Steps / Step">

    Break tutorials and setup instructions into steps, with labels, icons, and rich content for each stage.

    [View documentation](/docs/components/steps)

  </Card>
  <Card title="Surface">

    Frame a block of content with a consistent border and background, plus an optional name and description in its header.

  </Card>
  <Card title="Tabs / Tab">

    Present alternative content in named tabs, with optional icons for different platforms, workflows, or examples.

    [View documentation](/docs/components/tabs)

  </Card>
  <Card title="Tags">

    Display tags using configured colors. Document frontmatter renders these automatically; import `Tags` in React or register it explicitly for custom MDX usage.

    [View tag configuration](/docs/writting/frontmatter)

  </Card>
  <Card title="Video">

    Play local videos and remote MP4 URLs with custom playback, seeking, volume, speed, and fullscreen controls.

    [View documentation](/docs/components/video)

  </Card>
</Cards>

You can also [create and register your own components](/docs/components/customization). For page and layout components, see [Layouts and Pages](/docs/layout-and-page).
